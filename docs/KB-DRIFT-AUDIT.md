# KB-drift audit

This audits every defensive and transport control in the repo (all `ansible/roles/*`, the DPI/transport validator & probe `scripts/*`, the `emit-*` client generators, and the Terraform edge firewall) against the governing concepts in the censorship-bypass knowledge base (KB). One auditor per control located the governing concept(s) and classified the control; **both the MATCHES-KB and the CONTRADICTS-KB verdicts were then adversarially cross-checked** against what the repo actually does, before standing. This is a **report-only** run — no code was changed. It generalizes two confirmed seed findings: the former probe-ratelimit grepping for a `rejected`/`graylist` token REALITY never emits (`vless-graylist-active-probing-defense`), and validate-reality-target ignoring the exact-match SNI asymmetry (`sni-exact-match-vs-suffix-classification-2026`).

**Reliability note.** The adversarial pass mattered: of 8 first-pass CONTRADICTS-KB verdicts, **only 2 survived** — 6 were downgraded (see *Cross-check outcome*). The single-pass verdicts over-claimed mostly by (a) comparing repo code against a KB *template* the repo deliberately does not adopt, or (b) applying a Russian-cloud-AS-only pattern to this repo's foreign-VPS baseline. The **UNVERIFIED** rows were *not* put through that second pass — read them as candidates to confirm, not established defects.

## Cross-check outcome

Adversarial cross-check changed 7 verdicts — strong evidence that single-pass classification over-claims:

- **MATCHES-KB pass:** `nginx-xhttp` downgraded MATCHES → UNVERIFIED. The first auditor cited the June-2026 three-condition pattern as positive support; the cross-checker found it is scoped to Russian cloud ASes and does not apply to the foreign-VPS deployment.
- **CONTRADICTS-KB pass (8 reviewed, 2 upheld):**
  - Upheld: `watchdog` (dead `active_probing` detector), `subscription-host` (missing `X-Robots-Tag` + scrypt/sha256 doc mismatch + architectural HMAC/IP-log divergence).
  - `backup` → NO-KB-COVERAGE: the cited concept is draft advisory; the role meets its own stated retention floor.
  - `baseline`, `hysteria`, `probing-summary.sh` → UNVERIFIED: real deviations, but each measured against a draft/non-binding reference or with the count not actually corrupted.
  - `check-singbox-killswitch.py`, `emit-singbox.sh` → MATCHES-KB: both were correct for what this repo actually emits/targets; the first pass compared against a KB template tag the repo doesn't use, and applied the RU-AS-only fingerprint pattern to the foreign-VPS baseline.

## Generalization — systemic drift patterns

- **Log-string contracts are version-pinned but KB-unverified.** `watchdog` (live dead detector), `probing-summary.sh` (mislabeled but counting), `policy-ratelimit` (drift observed via its gauge), and `run-rkn-block-checker.sh` (upstream JSON schema) all key correctness on token strings or schemas the KB does not govern; on a silent contract break they emit zero/ERROR rather than failing loud.
- **On-host probes are structurally blind to the RU-path failure modes they claim to detect.** `warp-outbound`'s health gate, `tspu-canary.sh`'s WG probe, `check-ip-reputation.sh`'s abuse-feed queries, and `transport-reachability-matrix.sh`'s unfiltered CI half confuse local liveness with RU-vantage reachability — the recurring theme of the two seed findings.
- **Single-vantage or unkeyed probes map poorly to fingerprint specificity.** `tspu-canary.sh`'s DTLS probe, `scan-reality-targets.sh`'s overuse filter, and `test-tls-policing.sh`'s `N≈12` table embed values the KB documents as vantage-, ISP-cohort-, or measurement-axis-dependent, then treat them as invariants.
- **Hardcoded policy tables outrun their KB backing.** `validate-reality-target.sh`'s Avoid-tier ASN list, `asn-drift.sh`'s number-equality alert, and `check-ip-reputation.sh`'s abuse-feed heuristic encode policy for which no concept provides the enumerating evidence — the authority is internal `PROVIDER-NOTES.md` or implicit.
- **Pre-emptive coverage is thin in the post-deploy window.** `firewall` relies on a dynamic offender set populated only after traffic, while `active-probing-defenses` documents probes arriving within ~1 h of VPS creation.
- **Verdict-confidence caveat (method, not a control).** 6 of 8 first-pass CONTRADICTS-KB verdicts collapsed under cross-check — by comparing code to an unused KB template, or applying a Russian-cloud-AS-only pattern to the foreign-VPS baseline. The UNVERIFIED rows here were not put through that second pass; confirm each against the actual deployment scope before treating it as a defect.
