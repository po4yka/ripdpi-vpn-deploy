## Context

See `proposal.md` for motivation. Re-verification at `82b14824`:

- `ansible/roles/nginx-xhttp/files/nginx_transaction.py` `site_transaction` refuses `begin` (and check-mode admission) with `recovery-required` whenever `site.json` or `pending.json` exists under `/var/lib/vpn-nginx-publication/nginx.service`. `restore` already recovers an interrupted site completely (owner pending journal, witnesses, files, receipts, prior service state) but is reachable only through `ansible/playbooks/tasks/transport-ingress-restore.yml`, gated on `transport_site_transaction_active`, which `transport-ingress-begin.yml` sets only after a successful `begin` in the same run. The controller (`scripts/deploy-controller.py`) kills the Ansible process group on timeout or cancellation, so the rescue never runs on an interrupt. Egress next-run recovery exists (`transport-egress/tasks/runtime-prepare.yml`) but runs after ingress `begin`, which refuses first.
- The ordinary nginx publisher self-recovers its `pending.json` on next entry, but `cdn-front`, `subscription-host` and `probe-matrix-target` share the `nginx.service` state root and run after the protected block, so a pending-only journal left by them also blocks the next protected `begin`.
- `Makefile` `rotate-credentials`, `rollback-xray`, `rollback-config` have no prerequisites and no `--limit`; the plays are `hosts: vpn` with `forks = 5`. `ansible-config list` has no `ANSIBLE_LIMIT`. `scripts/render-inventory.sh` stamps every host with `env=` and `provider=`.
- `transport_runtime_rollback.py` (from `ab21b7fc`) resolves `<ver>-archive` / `<ver>-source-<commit>`, verifies the release receipt and digest, rewrites `XRAY_RUNTIME_BINARY` and `ExecStart` of `xray.service`, and the shared acceptance checks `/proc/<MainPID>/exe`. The private gateways also execute the pinned release but are owned by the egress transaction.

## Goals / Non-Goals

- Goal: the next deploy after an interrupted protected ingress transaction restores accepted authority through the existing compensation owner, and dry-run reports the condition without mutation.
- Goal: the three operator incident verbs cannot act on more than one named node or across environments.
- Goal: the runtime rollback branch is tested at its ownership boundary and documented truthfully.
- Non-goal: a new recovery verb, playbook, deploy-level lock, or second compensation sequence.
- Non-goal: rolling back private gateway units (separate task; needs a single-owner decision for gateway unit publication).
- Non-goal: closing the ingress-commit versus egress-finish window introduced by `ab21b7fc` (separate task).
- Non-goal: any provider, inventory, SSH or live action.

## Decisions

- Detect the interrupted site journal with a playbook-side `ansible.builtin.stat` (`follow: false`) of `/var/lib/vpn-nginx-publication/nginx.service/site.json` inside `transport-ingress-begin.yml`, after the desired request is declared and before capture. This mirrors the egress journal detection in `transport-egress-prepare.yml`, adds no helper CLI surface, and `--site restore` re-validates the journal and fails closed on a malformed one. Rejected: a new helper `status` action, which adds an argparse choice whose omission would fail every deploy and is caught only by Molecule.
- On an open site journal (non-check run): stat the egress outer helper, read its `status` when present, set `transport_site_transaction_active: true` and `_transport_egress_transaction_started` from the outer route's `open` flag (the same adoption `runtime-prepare.yml` performs for egress), then `ansible.builtin.fail` with a categorical message. The block's existing rescue performs quiesce, `--site restore` and egress rollback unchanged. Rejected: recover-and-continue in the same run, which would create a second recovery sequence and continue converging on a node whose accepted state has just been rewritten.
- In check mode the categorical fail fires without setting adoption facts; the rescue's terminal message must not claim compensation was attempted.
- Outer-route `status` failures are surfaced with the same categorical stderr extraction `transport-egress/tasks/rollback.yml` uses rather than a bare `no_log` failure.
- Before the adoption path runs the egress outer helper (`status`) as root, it reuses the existing root-owned ancestry and single-link regular-file admission, which is the former first task of `transport-egress/tasks/runtime-prepare.yml` moved with an unchanged body (renamed to cover helper execution) into the shared `transport-egress/tasks/helper-authority.yml` (refusal `consumer-helper-authority-refused`) and included from both. It runs only for non-check runs with an open site journal, so a refused admission fails closed before adoption with the journal retained and no compensation attempted. Rejected: a second copy of the Python in the playbook.
- A missing helper never reads as a closed route. The status task is skipped without the helper, so the unreadable-status refusal cannot see it and the adoption default `{"open": false}` would otherwise apply while the helper may have been deleted after egress began, leaving the rescue to restore ingress and delete the journal without rolling back an open outer transaction. The outer route's only durable open-route record is `outer.json` in `/var/lib/ripdpi/transport-runtime` (the helper's own `status` is `outer.json` present). With the helper missing, the playbook `stat`s the state directory and, when it is a directory, `outer.json` with `follow: false`, and refuses with the categorical `egress-outer-helper-missing` before adoption when the record exists in any form or the directory exists but is not a root-owned `0700` directory, the only state directory `Transaction._enter` accepts for the root-run status (a symlink or file cannot be judged without following it, and a directory the helper's own status would refuse as `unsafe-state-directory` is no proof of a closed route). Only an absent directory, or a root-owned `0700` one without the record, adopts with the route closed. The refusal names the complete `transport_runtime_*.py` helper set rather than one helper, because the status imports its siblings and the next deploy's shared admission, which accepts an absent file, requires every present one to be root-owned, single-link and not group- or world-writable under safe ancestry. No helper runs on this path, so the refusal needs no new admission, and check mode is unchanged. Rejected: running the missing helper's logic from the playbook, a second copy of the outer route's state semantics, and failing on every missing helper or existing state directory, which would wedge a node whose deploy was killed after ingress capture but before the egress role installed its helper, where no outer route state exists to roll back.
- Pending-only journals are recovered by the helper: in `site_transaction`, before receipt pre-admission and only for non-check `begin` with no `site.json`, call the existing `recover(state / "pending.json", "nginx.service")` under `unit_lock`. The in-lock refusal keeps checking both journals: recovery and capture take the lock separately (receipt pre-admission sits between them), so a pending journal that appears in that gap still fails closed. Recovery precedes receipt admission because an interrupted publish can leave disk bytes that disagree with prior receipt witnesses. Site journals stay the playbook's job because they need egress ordering. Check mode cannot recover, and the helper's refusal there is a generic `no_log` failure, so the playbook also `stat`s `pending.json` and, when `site.json` is absent, refuses check mode with the distinct category `interrupted-nginx-publication` stating that one deploy recovers it; non-check runs continue to the helper's `begin`.
- Exact-node targeting reuses one shared pre-task file, `ansible/playbooks/tasks/exact-node.yml`, tagged `always`, asserting `ansible_play_hosts_all | length == 1`, `ansible_limit is defined`, the alias pattern `^[A-Za-z0-9][A-Za-z0-9_.-]{0,127}$` and `ansible_limit == inventory_hostname`. Each of the three plays imports it as its first `pre_tasks` entry and sets `serial: 1` and `any_errors_fatal: true`. Make captures the alias before any recipe expands: when any of the three verbs or `require-exact-node` is a goal, a conditional block in the `Makefile` refuses every other goal in the same invocation, sets `.NOTPARALLEL` so verbs sharing an invocation run one at a time under an inherited `-j`, exports the raw `$(value ANSIBLE_LIMIT)` as `EXACT_NODE_ALIAS`, then overrides `ANSIBLE_LIMIT` to the literal reference `$$EXACT_NODE_ALIAS` and unexports it. No recipe, including the shared `require-inventory`, interpolates the alias into shell code; the shell expands the reference inside `--limit "$EXACT_NODE_ALIAS"`. `require-exact-node` validates `EXACT_NODE_ALIAS` in `python3` with `re.fullmatch` against the same alias pattern, which refuses an empty, blank or newline-terminated value (the play's `$` would admit a trailing newline). The three recipes start `ansible-playbook` under `env -u ANSIBLE_SKIP_TAGS -u ANSIBLE_RUN_TAGS`, because inherited tag selection would skip the `always`-tagged guard. `vpnd` `runner.ansible.rotate(ctx, alias)` requires the same alias grammar (raising `ValueError` otherwise), passes `--limit <alias>` and `ENV=<ctx.env>`, and removes the same two variables from the child environment. Rejected: a non-empty check (`$(strip $(ANSIBLE_LIMIT))`) with `--limit "$(ANSIBLE_LIMIT)"`, which lets Make and the shell parse operator text; and routing the verbs through `scripts/deploy-controller.py`, which requires SSH contexts and promotion inputs these incident verbs do not have.
- `rotate-credentials` additionally depends on `require-clean-source require-inventory pre-deploy-check` and asserts `hostvars[inventory_hostname]['env'] == lookup('env', 'ENV')` after the shared guard; its audit note records `node=$EXACT_NODE_ALIAS`. The rollback verbs get `require-inventory` only; they restore retained on-node authority and do not consume new secrets.
- Runtime rollback: extract the runtime branch of `transport_runtime_rollback.py` `main()` into `runtime_candidates(...)` without behaviour change so the candidate set is testable without root. No change to `transport_runtime_accept.py`, `release_versions` or gateway units.

## Contracts and ownership

- Ansible protected block (`ansible/playbooks/site.yml`): unchanged except the rescue's terminal message, which states whether accepted-generation recovery was attempted (owned by ANS-1791996166387223); `transport-ingress-begin.yml` gains detection, helper admission and adoption pre-steps; the rescue remains the single compensation owner.
- nginx publication helper: `site_transaction` begin recovers pending-only journals; check mode, `restore`, `commit` and the site-journal refusal are unchanged.
- transport-egress role: the helper admission task moves with an unchanged body (renamed to cover helper execution) to `tasks/helper-authority.yml`, shared by `runtime-prepare.yml` and `transport-ingress-begin.yml`; no behaviour change for `runtime-prepare.yml`.
- Make interface: three verbs gain a required `ANSIBLE_LIMIT` that must be one plain alias, captured literally into `EXACT_NODE_ALIAS`, with no other goal in the invocation and no inherited tag selection; `rotate-credentials` gains clean-source, pre-check and environment binding; `vpnd` `rotate()` gains a required alias argument. This is a deliberate breaking change with no compatibility path.
- Runtime publisher: operator runtime rollback candidate set contains only runtime-publisher-owned nodes; egress owns gateway units.
- Secrets: no schema change; `rotate-credentials` still reads `VPN_SECRETS_FILE` from `SECRETS_FILE`.

## Risks / Trade-offs

- Recovery requires a mutating `make deploy` after a refused dry-run, which runs the pre-block roles (baseline, firewall and others) before compensating. Mitigation: the runbook documents this as the single narrow exception, only when dry-run reports `interrupted-protected-ingress-transaction` or `interrupted-nginx-publication`, tells the operator to review the reported pre-block changes first, spells out `make deploy ANSIBLE_LIMIT='<exact-alias>' ANSIBLE_TAGS=` (empty tags, because an operator `.fleet.mk` may select tags that skip the protected block) and requires a full dry-run and deploy afterwards.
- The `interrupted-nginx-publication` recovery deploy continues past the protected block, so it applies protected staging, activation, commit and every later role that the refused dry-run (which stops at the start of the block) could not preview. Mitigation: the runbook allows it only while `make source-drift` passes and the decrypted secrets are the ones last deployed, so it reapplies reviewed state, and requires the normal preflight for any new revision afterwards. Rejected: stopping the non-check run after pending recovery, which needs a recovery-only helper entry point or a second compensation sequence.
- Adoption assumes no other live deploy targets the node; the old refusal was the only guard and the repository has no deploy-level lock. Mitigation: state the precondition in the runbook; do not claim races are benign.
- Per-node rotation turns fleet revocation into N invocations, and a forgotten node keeps a revoked credential valid. Mitigation: `RUNBOOK-rotate.md` and `RUNBOOK-deploy.md` state revocation is incomplete until every node is rotated and verified.
- Residual: the ingress-commit versus egress-finish window and gateway runtime rollback remain open and are tracked as separate tasks.

## Migration Plan

Forward: merge the source change; no node migration is required. Existing nodes without journals see only a read-only stat. A node already wedged by an old interruption is compensated by its next `make deploy`, after which the operator repeats dry-run and deploy. Operators update scripts that call the three verbs to pass `ANSIBLE_LIMIT=<alias>`.

Rollback: revert the commit; behaviour returns to fail-closed refusal on journals and unscoped verbs.

Gates: focused unit tests for the helper, the Ansible harness, the operator verb scope and the runtime rollback adapter; `ansible-lint` on changed playbooks; `make shellcheck`; `make check`; the native runtime lane in CI for the strengthened native assertions.
