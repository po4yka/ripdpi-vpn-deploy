## Context

`scripts/client_payload.py` materializes one device from decrypted SOPS documents into a canonical payload; `share_uri()` already renders the single P0 REALITY link from a sing-box payload, and `emit-qr.sh` reaches it through `emit-singbox.sh --share-uri`. The `ripdpi` payload format is the only one that already contains P0, P1 XHTTP (primary and alternate) and Hysteria2 outbounds with port hopping, and it already refuses Hysteria2 ECH and BBR profiles and XHTTP modes other than `auto` and `stream-up`. INCY 3.9.x documents `vless://` links with `type=xhttp` and `extra`, and `hysteria2://` links with `obfs`, `obfs-password`, `mport` and `mportHopInt`. See proposal.md for motivation.

## Goals / Non-Goals

- Goal: one read-only command that writes exact INCY links for one device to a private file.
- Goal: every link field comes from the canonical payload; no second materialization path.
- Non-goal: an INCY subscription format, `/sub/` publication or a device-lifecycle delivery format.
- Non-goal: AmneziaWG links (`awg://`, `amneziawg://`); AWG stays in the existing private `.conf` so the private key does not enter a refreshable link set.
- Non-goal: full Xray JSON for INCY, XHTTP pool tuning, payload failover.
- Non-goal: device acceptance; it is a separate authorized live step.

## Decisions

- Render links in a new `incy_links(payload)` beside `share_uri()` in `scripts/client_payload.py`, over the `ripdpi` payload. Rejected: a separate script with its own SOPS reading, which would duplicate materialization and drift.
- P0 links reuse the `share_uri()` field mapping for every REALITY outbound, not only one. P1 links use `security=tls`, `type=xhttp`, `sni`, `fp`, `host`, `path`, `mode=auto`. Hysteria2 links carry `<device>:<password>` in userinfo, `sni`, `insecure=0`, `up`/`down`, `obfs=salamander` and `obfs-password` when present, and `mport=<low>-<high>` with `mportHopInt=<whole seconds>` when hopping is set; the initial port stays in the authority part.
- Refuse instead of omit: XHTTP mode `stream-up` or any `xmux`, Hysteria2 ECH, BBR. These have no INCY link field or have unconfirmed semantics in Ferrum.
- Hysteria2 bandwidth hints (`up_mbps`, `down_mbps`) map to the INCY `up` and `down` link parameters, so no payload field is omitted. A field allowlist per outbound kind refuses any other field.
- Entry point: `emit-singbox.sh <device> --incy-links` feeds `make emit-incy CLIENT=… OUTPUT=…`, which writes through the existing owner-only private-file helper and refuses an existing path. Stdout reports only the path and per-protocol counts.
- Link fragment (name) uses the payload tag, which carries protocol and endpoint labels only.

## Contracts and ownership

- Scripts: `scripts/client_payload.py`, `scripts/emit-singbox.sh`; Make: `Makefile` target `emit-incy`.
- Secrets: same decrypted inputs as `emit-singbox`; no schema change in `secrets/schema.json`.
- No Terraform, Ansible, vpnd or publisher change.
- Docs: client delivery reference gains an INCY section; `docs/reference/make-targets.md` is regenerated by `make docs-reference`.
- Tests: `tests/unit/` file that covers `client_payload` share links, with literal expected links from a fixture.

## Risks / Trade-offs

- INCY or Ferrum parses a documented field differently → device acceptance on the Pixel per path before regular use; failures go back as refusals in the emitter.
- Link file is access material → owner-only file, refuse overwrite, no stdout values; the operator kit catalog records the path without values.
- XHTTP mode mismatch (`packet`/`connect` in INCY docs vs `packet-up`/`stream-up` here) → only `auto` is emitted.

## Migration Plan

Additive. No existing output changes, so no migration. Rollback is a revert of the source change; already written link files stay valid until the device credentials are revoked through `device-lifecycle`. Gates: narrow unit tests, `make shellcheck`, `make docs-check`, then `make check` because the change touches secrets handling; PR CI on the exact head.
