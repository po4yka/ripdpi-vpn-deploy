## Context

The existing roadmap implementations span canonical materialization, device identity,
Ansible runtime authority and real native adapters. The owner withdrew external
soak and recipient-device acceptance. Taskctl correctly refuses to erase historical
required evidence: this successor preserves all positive domain requirements while
prior external scopes are explicitly superseded through their terminal lifecycle.

## Goals / Non-Goals

- Goal: usable, isolated REALITY, direct XHTTP, Hysteria2 and AmneziaWG with exact per-device authority and real local authenticated traffic.
- Goal: measured alternate delivery and bounded tuning, secure topology probes, finite target validation, current local parser/runtime adoption and compensated failures.
- Goal: exact-source portable/native evidence with no selected skips, uncertain cleanup, render-only or refusal-only substitutes for positive behavior.
- Non-goal: external staging soak, physical/emulated recipients, production rollout, automatic promotion, provider operations, real authority issuance or redelivery.

## Decisions

- Reuse each existing domain capability path and stable requirement ID. Keep source and real-runtime evidence distinct; the new task cannot close until the accepted local behavior passes.
- Compose complete native regressions and all named four-protocol suites through `make transport-native-acceptance`. Run complete runtime transactions in a separate fresh systemd root to preserve foreign-authority refusal.
- Use actual pinned engines and synthetic private authority inside owned Linux network namespaces/TUN. Canonical emitters and adapters remain the data path; fixture DNS, peers and certificates terminate real traffic locally.
- Bind XHTTP mode and typed bounded-pool controls to the exact verified engine. Preserve primary and alternate results independently; working fallback never conceals a degraded endpoint.
- Keep trusted TLS/SAN validation and matching Salamander/ECH settings. Bound resolver, handshake, HTTP, notification and cleanup owners; refuse excessive or malformed input before authority publication.
- Keep existing guarded runtime recovery, no-leak policy and immutable admission/rollback rules. Unknown release/advisory eligibility continues to block promotion; local execution does not claim deployment eligibility.
- Archive maintenance relocates only links to owned change documents. Superseded records retain their original close receipt; validation checks the exact link projection from the archive’s reachable terminal source. Repeated archive invocation preserves lifecycle timestamps and spec state.
- Retain existing taskctl gates. The old scope is superseded rather than falsely recording external evidence as passed or inventing a shared operational owner.

## Contracts and ownership

- Terraform and cloud-init retain infrastructure/bootstrap ownership. Only credential-free mock regression coverage runs locally.
- Ansible retains runtime ownership: watchdog, Xray/nginx, Hysteria, AWG, firewall and their shared transaction/controller interfaces.
- Canonical Python scripts own consumed-payload identity, selected endpoint materialization, typed semantics, native liveness conversion and bounded target hygiene.
- Secrets/schema examples retain structure and typed bounds; no operator plaintext, deployed inventory, provider credential or state enters tests.
- Make and CI own complete no-skip entry points. One primary writer serializes shared schemas, snapshots, source and portfolio metadata in the dedicated worktree.

## Risks / Trade-offs

- Local traffic cannot establish external path survival or recipient adoption: those outcomes remain excluded and unclaimed.
- Runtime selection can diverge from a pin alone: real process identity, warm/unchanged convergence, authenticated requests and compensation remain required.
- Broad native checks need actual dependencies and isolated roots: missing tools, privilege, process cleanup or selected execution fails the lane.
- Optional profile performance is path-dependent: retain measured local observations without claiming an external improvement.
- Historical scope withdrawal cannot satisfy an old evidence gate: commit terminal supersession and archive through taskctl before purging, preserving truthful history and the successor link.

## Migration Plan

Canonical RIPDPI-format XHTTP payloads now require explicit mode and preserve
selected exact-engine bounded-pool settings. Update all owned adapters and regenerate local
artifacts together; do not add compatibility shims. Existing operator material
remains untouched. Complete local source and native validation, commit review
with exact evidence, archive the completed local change and commit its terminal
state before a later purge. External rollout, promotion and recipient redelivery
require their own future scope and authorization.
