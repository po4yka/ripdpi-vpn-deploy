## Purpose

Define the pinned OpenTofu command-line tool that every infrastructure root, script, CI job and vpnd command uses, and the offline checks that must pass under it before state moves to an encrypted backend.

## ADDED Requirements

### Requirement: REQ-TOFU-PIN — One exact OpenTofu version everywhere

`mise.toml`, every workflow that runs infrastructure commands and every root's `required_version` MUST name the same exact OpenTofu release. CI MUST install it by checksum or by a SHA-pinned action. No workflow, script or Make target MUST call a `terraform` binary.

#### Scenario: Version drift

- **WHEN** `mise.toml` and a workflow name different OpenTofu versions
- **THEN** the existing toolchain-pin test fails and names both locations

#### Scenario: Leftover terraform call

- **WHEN** a script or recipe still invokes `terraform`
- **THEN** a unit test that runs the script with only a `tofu` stub on `PATH` fails

### Requirement: REQ-TOFU-LOCKS — Provider locks come from the OpenTofu registry

Every root MUST commit a `.terraform.lock.hcl` generated by `tofu providers lock` with hashes for `linux_amd64`, `darwin_arm64` and any other platform CI or the operator uses. `tofu init` MUST NOT need `-upgrade` on a clean checkout.

#### Scenario: Missing platform hash

- **WHEN** the CI runner initializes a root whose lock lacks `linux_amd64` hashes
- **THEN** `tofu init` fails closed instead of trusting the downloaded provider

### Requirement: REQ-TOFU-CHECKS — Existing tests and policies pass unchanged

`make tf-test`, `make tf-policy-verify`, `make validate` and `make tf-conftest` MUST pass under OpenTofu with the existing `mock_provider` tests and Rego policies. A test MAY be edited only where OpenTofu output or test semantics differ; each such edit MUST name the difference in the commit message. A test whose Terraform-only feature has no OpenTofu equivalent MAY be retired only with operator approval recorded in `design.md`.

#### Scenario: Plan JSON shape differs

- **WHEN** a conftest policy reads a `tofu show -json` field that differs from Terraform's
- **THEN** the policy is adjusted and its `_test.rego` case proves the same denial as before

### Requirement: REQ-TOFU-STATE-COMPAT — Existing local state reads without change

Before W3, the operator MUST be able to run `make plan` for every production root against the existing local state and get no resource changes. A non-empty plan MUST stop the migration.

#### Scenario: First plan after the switch

- **WHEN** the operator runs `make PROVIDER=<p> ENV=prod plan` with OpenTofu
- **THEN** the plan shows no changes and the policy check passes

#### Scenario: Rollback

- **WHEN** the no-change plan fails for a root
- **THEN** the operator reverts the toolchain commit; the state file was not rewritten by a read-only plan
